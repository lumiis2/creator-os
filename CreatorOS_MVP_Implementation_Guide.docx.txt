CreatorOS
MVP Architecture & Implementation Guide
Senior Engineering Reference · Phase 1 Build
March 2026
	

1. Architecture Overview
CreatorOS MVP uses a monorepo with three deployment targets: a Next.js app (Vercel), a background worker process (Railway), and a managed Postgres database (Neon). The AI layer is stateless — it reads context from the database on each request and streams tokens back to the client. No separate AI server is required.

1.2 Data flow — chat request
User types message
      │
      ▼
POST /api/chat/stream
      │
      ├─ 1. Auth middleware: validate JWT session
      ├─ 2. Rate limiter: check token budget (Redis)
      ├─ 3. Context builder:
      │       ├─ Load creator_profile from Postgres
      │       ├─ Load analytics summary (last 7 days) from Postgres
      │       └─ Load last 20 chat_messages for this session
      ├─ 4. Build system prompt (deterministic, no AI)
      ├─ 5. Call Anthropic claude-sonnet-4-6 with streamText()
      ├─ 6. Stream SSE tokens → browser
      └─ 7. On complete: persist assistant message + token count
	

1.3 Data flow — analytics sync
Trigger: user clicks "Sync now" OR cron fires at 06:00 UTC
      │
      ▼
POST /api/analytics/sync  (or BullMQ job)
      │
      ├─ 1. Load platform_connection (decrypt access_token)
      ├─ 2. Call YouTube Data API v3 + YouTube Analytics API
      ├─ 3. Parse & validate raw response (Zod)
      ├─ 4. Compute derived metrics DETERMINISTICALLY:
      │       engagement_rate = (likes+comments+shares) / views
      │       follower_growth_rate = (current - previous) / previous
      ├─ 5. Upsert analytics_snapshot row in Postgres
      ├─ 6. Upsert video_metric rows in Postgres
      └─ 7. Invalidate Redis cache key for this user's dashboard

Key trade-off: monorepo vs. separate services
MVP uses a single Next.js monorepo with one Railway worker. This is intentional — you ship faster, debug
faster, and share types between frontend and backend without an extra API layer. Extract microservices
only when you have a concrete scaling bottleneck. The folder structure below already isolates concerns
so the extraction path is clean when needed.

4. MVP Scope — Strict Boundaries


4.1 In scope (Phase 1)
* User authentication (email/password + Google OAuth)
* Guided onboarding wizard (niche, content style, posting goals)
* Creator profile CRUD with all AI-relevant fields
* YouTube OAuth connection + analytics sync
* Dashboard: KPI cards, views trend chart, top videos table
* AI chat agent with profile context + analytics injection + history
* Simple workspace: create / edit / delete items with stage field (idea / draft / script)
* Token budget enforcement (Redis counter, plan limit check)
* Stripe Billing: Starter (free) + Creator Pro ($12) subscription setup


4.2 Explicitly out of scope (Phase 1)
* TikTok / Instagram integration — API access too restricted; CSV import is Phase 3
* Kanban drag-and-drop pipeline — Phase 2; flat list is sufficient for MVP
* Time tracker — Phase 2
* AI insight layer in dashboard — Phase 3
* Autonomous niche research — Phase 2 (Tavily integration)
* Video analysis / image analysis — Phase 3
* Script-to-video performance linking — Phase 2
* RAG / vector embeddings — pgvector column stubbed in schema; populated in Phase 2


Design principle: stub, don't skip
For every out-of-scope feature, the database column or API route stub is created NOW with a
"not implemented" 501 response. This means Phase 2 work is additive, never requiring a schema migration
to add a column that should have been there from day 1.

5.2 Service layer architecture
Each domain has a service module that the API routes call. API routes handle only HTTP concerns (parsing, auth, response). Services handle business logic.


// Pattern — every API route follows this shape:
// apps/web/src/app/api/analytics/snapshot/route.ts


import { NextRequest, NextResponse } from "next/server";
import { requireAuth } from "@/lib/auth";
import { getAnalyticsSummary } from "@/lib/analytics/compute";
import { getLatestSnapshot } from "@creator-os/db/queries/analytics";


export async function GET(req: NextRequest) {
  // 1. Auth
  const session = await requireAuth(req);
  if (!session) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });


  // 2. Fetch data (deterministic — no AI)
  const snapshot = await getLatestSnapshot(session.userId);
  if (!snapshot) return NextResponse.json({ data: null, synced: false });


  // 3. Compute derived metrics (pure functions)
  const summary = getAnalyticsSummary(snapshot);


  // 4. Return
  return NextResponse.json({ data: summary, syncedAt: snapshot.createdAt });
}
	

5.3 Analytics processing — deterministic rules
CRITICAL: No AI in analytics computation
Every metric shown in the dashboard is computed by pure TypeScript functions from raw Postgres data.
The LLM never touches numbers. If a metric cannot be computed deterministically, it is shown as null,
never estimated or hallucinated.
	

Metrics computed in lib/analytics/compute.ts:
* engagement_rate: (likes + comments + shares) / views * 100 — returns null if views === 0
* follower_growth_rate: (current_followers - prev_followers) / prev_followers * 100
* avg_views_7d: SUM(views) / COUNT(videos) WHERE published_at > now() - 7 days
* top_videos: ORDER BY views DESC LIMIT 5 — pure SQL, no scoring model
* best_posting_day: GROUP BY EXTRACT(DOW FROM published_at) — deterministic aggregation

6.3 State management
Server state (TanStack Query)
	Analytics snapshot, video list, workspace items, chat history. Cache with stale-while-revalidate. Optimistic updates on workspace mutations.
	Client state (Zustand)
	Active chat session ID, in-flight message content (streaming), draft workspace item being edited.
	Form state (React Hook Form)
	Profile form, new workspace item dialog, onboarding wizard steps.
	URL state
	Active workspace stage filter (?stage=draft), chat session (?session=uuid). Deep-linkable.
	Auth state (Auth.js session)
	useSession() hook. Redirect middleware in middleware.ts protects all (app) routes.
	

6.4 Key design decisions
* No client-side analytics computation. All charts receive pre-computed data from the API. The frontend only renders numbers; it never calculates them.
* SSE not WebSockets for chat. Server-Sent Events via the Vercel AI SDK streamText() response. Simpler infrastructure, no persistent connection server needed.
* Markdown rendering in chat. Use react-markdown + remark-gfm for assistant messages. Creators frequently receive formatted responses (bullet lists, headers).
* Skeleton loaders everywhere. TanStack Query's isLoading state drives Skeleton components. No empty white screens.


7. AI System Design


7.1 System prompt architecture
The system prompt is assembled fresh on every request by context-builder.ts. It has four sections concatenated in order. The first two sections (identity + profile) qualify for Anthropic prompt caching — they change at most once per user per day.

7.2 Analytics context compression rules
Analytics are injected as compressed prose — never as raw JSON
Raw JSON wastes tokens and makes the LLM extract numbers itself (hallucination risk).
The context-builder.ts compresses a full analytics snapshot into ~300 tokens of structured prose.
Only include metrics that are relevant to social media strategy decisions.
	

What to include in analytics context:
* 7-day and 30-day view totals with percentage change vs previous period
* Current subscriber/follower count + weekly net change
* Average engagement rate (computed deterministically)
* Top 3 performing videos: title, views, ER
* Bottom 1 performing video (useful for the agent to reference what not to repeat)
* Best performing day of week (last 30 days)
* Data freshness timestamp


What to EXCLUDE:
* Raw view counts per video for all videos (only top/bottom)
* Impressions, reach, CPM (too granular for conversational context)
* Historical data beyond 30 days (history can be queried on demand)


7.3 Token budget enforcement
Tier
	Monthly limit
	Starter (free)
	50 messages (~75K tokens)
	Creator Pro $12
	500 messages (~750K tokens)
	Creator Max $29
	Unlimited (soft cap at 5K messages for abuse prevention)
	

Budget check flow in token-budget.ts:
* On every POST /api/chat/stream — before building context — check Redis counter: token_budget:{userId}:{yearMonth}
* If messages_used >= plan_limit → return 429 with remaining=0 and upgrade prompt
* After successful completion → INCR Redis counter + persist token count to token_usage table
* Redis key TTL is set to end of calendar month — auto-resets


7.4 Proactive vs passive mode
Controlled by creator_profiles.agent_mode field. The context-builder injects different instructions:
// Proactive mode injection (appended to Section 1):
"When the user opens a chat session, greet them with one specific,",
"data-driven insight from their recent analytics. Be brief (2-3 sentences).",
"Then ask one follow-up question to understand their current priority."


// Passive mode injection:
"Wait for the user to ask a question. Do not open with unsolicited insights.",
"Respond directly and concisely when asked."

8.3 creator_profiles
CREATE TABLE creator_profiles (
  user_id           UUID PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE,
  display_name      TEXT,
  niche             TEXT,                  -- e.g. "fitness"
  sub_niche         TEXT,                  -- e.g. "home workouts"

8.4 platform_connections
CREATE TABLE platform_connections (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id           UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  platform          TEXT NOT NULL,         -- "youtube" | "instagram" | "tiktok"
  platform_user_id  TEXT NOT NULL,         -- channel ID from platform
  display_name      TEXT,                  -- channel name
  access_token_enc  TEXT NOT NULL,         -- AES-256-GCM encrypted via KMS
  refresh_token_enc TEXT,                  -- encrypted
  token_expires_at  TIMESTAMPTZ,
  scopes            TEXT[],

10.2 Analytics compute layer (lib/analytics/compute.ts)
import type { AnalyticsSnapshot } from '@creator-os/db';
import type { VideoMetric } from '@creator-os/db';


// All functions are pure — no side effects, no AI, fully testable


export function computeEngagementRate(
  views: number,
  likes: number,
  comments: number,
  shares: number,
): number | null {
  if (views === 0) return null;
  return ((likes + comments + shares) / views) * 100;
}


export function computeGrowthRate(
  current: number,
  previous: number,
): number | null {
  if (previous === 0) return null;
  return ((current - previous) / previous) * 100;
}


export interface AnalyticsSummary {
  subscribers: number;
  totalViews: number;
  views7d: number;
  views7dChange: number | null;  // % vs prev 7d
  subsGained7d: number;
  avgEngagementRate7d: number | null;
  dataAsOf: Date;
  platform: string;
}


export function buildAnalyticsSummary(
  current: AnalyticsSnapshot,
  previous: AnalyticsSnapshot | null,
): AnalyticsSummary {
  return {
    subscribers:        current.subscribers ?? 0,
    totalViews:         current.totalViews ?? 0,
    views7d:            current.views7d ?? 0,
    views7dChange:      previous?.views7d
      ? computeGrowthRate(current.views7d ?? 0, previous.views7d)
      : null,
    subsGained7d:       current.subsGained7d ?? 0,
    avgEngagementRate7d: current.avgEr7d ? Number(current.avgEr7d) : null,
    dataAsOf:           current.createdAt,
    platform:           current.platform,
  };
}


// Format summary as compressed prose for AI context injection
export function formatAnalyticsForAI(summary: AnalyticsSummary): string {
  const changeStr = summary.views7dChange !== null
    ? `(${summary.views7dChange > 0 ? '+' : ''}${summary.views7dChange.toFixed(1)}% vs prev 7d)`
    : '(no comparison data)';


  return [
    `=== Performance Summary (${summary.platform}, last 7 days) ===`,
    `Total views: ${summary.views7d.toLocaleString()} ${changeStr}`,
    `Subscribers: ${summary.subscribers.toLocaleString()} (+${summary.subsGained7d} this week)`,
    summary.avgEngagementRate7d !== null
      ? `Avg engagement rate: ${summary.avgEngagementRate7d.toFixed(1)}%`
      : 'Avg engagement rate: insufficient data',
    `Data as of: ${summary.dataAsOf.toISOString().split('T')[0]}`,
  ].join('\n');
}

You are direct, data-literate, and focused exclusively on helping creators grow their online presence.
You only discuss topics related to social media strategy, content creation, analytics, and
audience growth. If asked about anything unrelated, politely redirect to your area of expertise.

  const lines = [
    '=== Creator Profile ===',
    profile.displayName ? `Creator: ${profile.displayName}` : '',
    profile.niche ? `Niche: ${profile.niche}${profile.subNiche ? ` / ${profile.subNiche}` : ''}` : '',
    profile.contentStyle?.length ? `Content style: ${profile.contentStyle.join(', ')}` : '',
    profile.audienceDesc ? `Audience: ${profile.audienceDesc}` : '',
    profile.postingGoalFreq ? `Posting goal: ${profile.postingGoalFreq}x per week` : '',
  ].filter(Boolean);
  return lines.join('\n');
}


function buildModeInstruction(mode: string): string {
  return mode === 'proactive'
    ? 'Open each new conversation with one specific, data-driven insight from recent analytics. Be brief (2-3 sentences). Then ask one follow-up question.'
    : 'Wait for the user to ask a question. Respond directly without unsolicited insights.';
}


export interface ChatContext {
  systemPrompt: string;
  messages: CoreMessage[];
}


export async function buildChatContext(
  userId: string,
  sessionId: string,
  profile: CreatorProfile,
): Promise<ChatContext> {
  // Load analytics (parallel)
  const [currentSnap, prevSnap, recentMessages] = await Promise.all([
    getLatestSnapshot(userId),
    getPreviousSnapshot(userId, 7),
    getRecentMessages(sessionId, 20),
  ]);


  // Build analytics context (deterministic)
  let analyticsSection = '=== No analytics data yet. User has not synced. ==='
  if (currentSnap) {
    const summary = buildAnalyticsSummary(currentSnap, prevSnap);
    analyticsSection = formatAnalyticsForAI(summary);
  }


  // Assemble system prompt
  const systemPrompt = [
    IDENTITY_PROMPT,
    buildModeInstruction(profile.agentMode ?? 'proactive'),
    '',
    buildProfileSection(profile),
    '',
    analyticsSection,
  ].join('\n');


  // Map DB messages to Vercel AI SDK format
  const messages: CoreMessage[] = recentMessages.map(m => ({
    role: m.role as 'user' | 'assistant',
    content: m.content,
  }));


  return { systemPrompt, messages };
}
	

10.4 Streaming chat API route (app/api/chat/stream/route.ts)
import { NextRequest } from 'next/server';
import { streamText } from 'ai';
import { anthropic } from '@ai-sdk/anthropic';
import { requireAuth } from '@/lib/auth';
import { buildChatContext } from '@/lib/ai/context-builder';
import { checkAndIncrementBudget } from '@/lib/ai/token-budget';
import { getCreatorProfile } from '@creator-os/db/queries/profiles';
import { getOrCreateSession, persistMessage } from '@creator-os/db/queries/chat';
import { z } from 'zod';


const RequestSchema = z.object({
  message: z.string().min(1).max(4000),
  sessionId: z.string().uuid().optional(),
});


export async function POST(req: NextRequest) {
  // 1. Auth
  const session = await requireAuth(req);
  if (!session) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }


  // 2. Parse & validate body
  const body = await req.json().catch(() => null);
  const parsed = RequestSchema.safeParse(body);
  if (!parsed.success) {
    return Response.json({ error: 'Invalid request' }, { status: 400 });
  }
  const { message, sessionId: existingSessionId } = parsed.data;


  // 3. Token budget check (Redis)
  const budget = await checkAndIncrementBudget(session.userId, session.plan);
  if (!budget.allowed) {
    return Response.json({
      error: 'Monthly message limit reached',
      messagesUsed: budget.used,
      limit: budget.limit,
      upgradeUrl: '/profile#billing',
    }, { status: 429 });
  }


  // 4. Load profile + get/create session (parallel)
  const [profile, chatSession] = await Promise.all([
    getCreatorProfile(session.userId),
    getOrCreateSession(session.userId, existingSessionId),
  ]);


  // 5. Build AI context (profile + analytics + history)
  const { systemPrompt, messages: history } = await buildChatContext(
    session.userId,
    chatSession.id,
    profile,
  );


  // 6. Persist user message before streaming
  await persistMessage({
    sessionId: chatSession.id,
    userId: session.userId,
    role: 'user',
    content: message,
  });


  // 7. Stream response from Claude
  const result = streamText({
    model: anthropic('claude-sonnet-4-6'),
    system: systemPrompt,
    messages: [...history, { role: 'user', content: message }],
    maxTokens: 1000,
    onFinish: async ({ text, usage }) => {
      // 8. Persist assistant message + token count
      await persistMessage({
        sessionId: chatSession.id,
        userId: session.userId,
        role: 'assistant',
        content: text,
        tokenCount: usage.completionTokens,
      });
    },
  });


  // 9. Return SSE stream with session ID header
  return result.toDataStreamResponse({
    headers: { 'X-Session-Id': chatSession.id },
  });
}
	

10.5 Token budget enforcement (lib/ai/token-budget.ts)
import { redis } from '@/lib/redis';


const PLAN_LIMITS: Record<string, number> = {
  starter: 50,
  pro:     500,
  max:     5000,  // soft cap for abuse prevention
};


function getBudgetKey(userId: string): string {
  const now = new Date();
  const yearMonth = `${now.getFullYear()}-${String(now.getMonth() + 1).padStart(2, '0')}`;
  return `token_budget:${userId}:${yearMonth}`;
}


export interface BudgetResult {
  allowed: boolean;
  used: number;
  limit: number;
}


export async function checkAndIncrementBudget(
  userId: string,
  plan: string,
): Promise<BudgetResult> {
  const limit = PLAN_LIMITS[plan] ?? PLAN_LIMITS.starter;
  const key = getBudgetKey(userId);


  // Atomic: get current count
  const current = await redis.get<number>(key) ?? 0;


  if (current >= limit) {
    return { allowed: false, used: current, limit };
  }


  // Increment and set TTL to end of month
  const newCount = await redis.incr(key);
  if (newCount === 1) {
    // First use this month — set TTL to end of month
    const endOfMonth = new Date();
    endOfMonth.setMonth(endOfMonth.getMonth() + 1, 1);
    endOfMonth.setHours(0, 0, 0, 0);
    const ttlSeconds = Math.floor((endOfMonth.getTime() - Date.now()) / 1000);
    await redis.expire(key, ttlSeconds);
  }


  return { allowed: true, used: newCount, limit };
}

10.7 YouTube sync worker (apps/worker/src/workers/youtube-sync.ts)
import { Job } from 'bullmq';
import { fetchYouTubeChannelStats, fetchYouTubeVideos } from '../lib/youtube';
import { decryptToken } from '../lib/kms';
import { normaliseYouTubeStats } from '../lib/normalise';
import { computeEngagementRate } from '../lib/compute';
import { db, platformConnections, analyticsSnapshots, videoMetrics } from '@creator-os/db';
import { eq } from 'drizzle-orm';


export interface YouTubeSyncJobData {
  userId: string;
  connectionId: string;
}


export async function processYouTubeSync(job: Job<YouTubeSyncJobData>) {
  const { userId, connectionId } = job.data;


  // 1. Load connection + decrypt token
  const connection = await db.query.platformConnections.findFirst({
    where: eq(platformConnections.id, connectionId),
  });
  if (!connection) throw new Error(`Connection ${connectionId} not found`);


  const accessToken = await decryptToken(connection.accessTokenEnc);


  // 2. Set sync_status = syncing
  await db.update(platformConnections)
    .set({ syncStatus: 'syncing' })
    .where(eq(platformConnections.id, connectionId));


  try {
    // 3. Fetch raw data from YouTube APIs
    const [channelStats, videos] = await Promise.all([
      fetchYouTubeChannelStats(accessToken),
      fetchYouTubeVideos(accessToken),
    ]);


    // 4. Normalise (raw → DB schema shape)
    const snapshot = normaliseYouTubeStats(channelStats, userId, connectionId);


    // 5. Upsert snapshot (all computations are pure functions)
    await db.insert(analyticsSnapshots)
      .values(snapshot)
      .onConflictDoUpdate({
        target: [analyticsSnapshots.userId, analyticsSnapshots.platform, analyticsSnapshots.snapshotDate],
        set: { ...snapshot, createdAt: new Date() },
      });


    // 6. Upsert video metrics
    for (const video of videos) {
      const er = computeEngagementRate(video.views, video.likes, video.comments, video.shares);
      await db.insert(videoMetrics)
        .values({ ...video, userId, connectionId, engagementRate: er?.toString() ?? null })
        .onConflictDoUpdate({
          target: [videoMetrics.userId, videoMetrics.platform, videoMetrics.platformVideoId],
          set: { views: video.views, likes: video.likes, syncedAt: new Date() },
        });
    }


    // 7. Mark sync complete
    await db.update(platformConnections)
      .set({ syncStatus: 'idle', lastSyncedAt: new Date(), syncError: null })
      .where(eq(platformConnections.id, connectionId));


  } catch (err) {
    // 8. Persist error, reset status
    await db.update(platformConnections)
      .set({ syncStatus: 'error', syncError: String(err) })
      .where(eq(platformConnections.id, connectionId));
    throw err;  // BullMQ handles retry
  }
}
